# 导出身份与重试

从真实代码读取 composition ID、entry、fps、durationInFrames、尺寸和声音入口。记录预计秒数为 `durationInFrames / fps`，不要依据旧 README 推断当前成片。

先检查目标目录的同名文件及时间。保留用户已有版本；本次改版使用清晰版本名称，临时输出在工程内。渲染成功后再复制或移动到展示目录并核对文件散列。

CLI 的位置参数顺序为：

```text
remotion render <entry> <composition-id> <output-path> [options]
```

曾见输出路径被错当成 composition ID，通常是参数传递方式错误。先核对 CLI 收到的三个位置参数，不要对一个不存在的 ID 持续重试。Windows 路径用独立参数/正确引号，不把整个命令拼成多层 shell 字符串。

复杂项目可使用项目现有 Node 渲染入口及 Remotion renderer API。若项目自带渲染/审查辅助脚本，先读其参数和输出行为，确认 composition、帧范围、覆盖策略与当前依赖版本；不要把其他项目的 composition ID、并发数或编码参数当成默认值。

小段检查解决素材、字体和音频缺失后才进行长渲染。运行中的导出保留进度，等待真实结束；出现失败时记录退出码、最后错误和是否产生部分文件。部分 MP4 不进入作品目录。

渲染成功的最低证据：进程成功、目标文件真实存在、媒体能解析、时长/尺寸/音轨与本次配置一致。发布网站或上传仓库属于另外的用户授权范围，不由“导出”自动触发。
