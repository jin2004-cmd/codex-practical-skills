# 文字边界、抽帧与观众审美

## 先审实际可见文本

从 composition 和子组件收集片名、章节、正文、标签、角注和片尾。逐条检查是否是给观众看的知识表达。制作说明、遮罩方向、实现方法、暂存版本标记应放工程文档；藏品名称、朝代与必要署名不要误删。

安全区以当前画幅和排版设计定义，不能直接套用竖屏社交平台的中心 75%规则。确认字体实际加载；字体替换会改变断行、字宽和文字高度。

## 自动逐帧文字检查

项目可接入 `VideoTextAudit.tsx` 这样的检查组件，在每个 Remotion 帧都记录可见文字的 DOM 边界、字体与透明度，并由审核渲染脚本汇总。检查组件使用 frame 驱动，不依赖真实时间；不要让它改变观众成片。

优先检测：文字超出设计安全区、裁切容器、转场时正文与标签相撞、动画早退或晚退。透明度接近零、遮罩遮住或带合法进出场运动的文本要按明确条件处理；记录例外原因，不能简单忽略全部边界报警。

自动检查覆盖的是几何和时序。它不能判断中文措辞是否自然、文字与历史语境是否恰当、字体是否有气质、主体是否被视觉抢占或构图是否恢弘。SVG path 中的文字、canvas 和烘焙在图片里的文字也可能不在 DOM 审计范围内。

若项目接入自定义 DOM 文字审计，先确认 composition 确实启用了审计组件、审计覆盖的帧数达到目标，并按当前画幅、字体、平台安全区设置阈值。零条日志或零个样本不代表没有问题。几何报警需回到对应图像与转场时序人工确认。

## 抽帧计划

按镜头内容安排稳定帧；在每个重要入场、出场、转场取前/中/后的邻近帧。用带帧号和秒数的联系表快速定位，再看需要修复帧的原尺寸图。

审核重点是主句阅读顺序、角注与图像边缘关系、遮挡、字距/行距、对比度、纹理是否吞字、相邻帧是否跳位。对转场与粒子还要播放短段观察，单帧不足以证明运动连贯。

如果全片有 3600 帧而只目视查看了 100 帧，就写“3600 帧自动边界/技术检查，100 帧人工视觉检查”，不能写“每一帧美学通过”。源代码改动后，旧抽帧不能证明新版本；重新检查受影响场景和转场。
