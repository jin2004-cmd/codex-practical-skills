# Interview Debrief (面试复盘)

Turn a raw interview transcript into a structured debrief report.
The goal is not to judge — it is to find **what worked, what didn't, and exactly how to fix it next time**.

## Input

Accept these formats:

| 格式 | 来源 | 处理方式 |
|------|------|---------|
| 飞书妙记导出 `.md` / 文本 | 飞书会议 → 妙记 → 导出 | 直接 Read |
| 逐字稿文本（`.txt` / `.md`） | 用户粘贴 / 文件 | 直接 Read |
| 音频文件（`.mp3` / `.m4a` / `.wav`） | 录音文件 | `AudioTranscribe` tool 转写后再分析 |
| 截图 / 照片 | 面试笔记照片 | Read 看图（⚠️ Houston准则：看不到就直说） |

## Step 1: Raw data extraction

1. **读完全文**，报出总时长 / 总字数
2. **分段标记**：按问答对拆分，标注：
   - Q = 面试官问题
   - A = 用户回答
   - R = 追问/反问
   - S = 自我介绍段
3. **时间戳对齐**：如果原文带时间戳，保留关键节点（自我介绍结束、每个问题开始/结束）

## Step 2: Highlight extraction (亮点挖掘)

从回答中找**真正有价值的点**，不是泛泛夸奖：

| 类型 | 判定标准 | 示例 |
|------|---------|------|
| **框架型回答** | 用了结构化方法（步骤/维度/框架） | 六步判断框架、STAR法则、SWOT |
| **数据支撑** | 回答里带了可验证的数字/结果 | "50万播放""专业前3%" |
| **行业洞察** | 展现了对岗位/行业的理解深度 | "内容风控比泛运营更适配我" |
| **差异化牌** | 别人没有的独特组合 | AIGC全链路 + 自研Agent + 海外社媒 |

**每条亮点必须引用原文片段**（带时间戳），不许概括后丢失细节。

## Step 3: Problem flagging (问题诊断)

这是最有价值的部分。按严重程度分四级：

### 🔴 红灯（致命问题 — 很可能直接导致挂掉）

| 问题类型 | 检测信号 | 典型案例 |
|---------|---------|---------|
| **立场冲突** | 回答与岗位核心价值观矛盾 | "欺骗没损失" vs 风控政策岗 |
| **硬条件暴露** | 主动说出不利事实且无补救 | "我不怎么用快手"投快手 |
| **时间线矛盾** | 到岗时间/实习时长说法不一致 | 简历写1月到岗，面试说12月 |
| **自曝短板** | 主动强调自己不会的东西 | "我XX确实不太行"（无转折） |

### 🟡 黄灯（减分项 — 不致命但拉低印象）

| 问题类型 | 检测信号 |
|---------|---------|
| **口语碎片过多** | "就是""然后""那个"占比 > 15% |
| **回答跑题** | 问A答B，或绕了两圈没给结论 |
| **反问环节浪费** | 问了无关紧要的问题 / 没问任何问题 |
| **过度谦虚/过度自信** | 要么贬低自己要么吹过头 |

### 🟢 绿灯（可改进但本次不扣分）

- 表达可以更精炼
- 某个例子可以换一个更有力的
- 语速/音量/肢体语言（文字逐字稿看不到的不判）

### ⚪ 观察项（信息不足，标出来待确认）

- 面试官的反应（逐字稿里没有）
- 是否有笔试/代码题
- 具体用了什么面试形式（结构化/半结构化/压力面）

## Step 4: Scoring (综合评分)

```
【总评】🟡 黄灯偏红灯 / 🟢 绿灯 / 🔴 红灯

能力匹配度：  X/10  （知识/技能够不够用）
表达清晰度：  X/10  （说清楚了吗）
岗位契合度：  X/10  （这个人适合这个岗吗）
时间/流程：  X/10  （到岗时间/流程有没有硬伤）

核心矛盾：一句话总结"为什么是这个评分"
```

## Step 5: Actionable improvement plan (改进方案)

**不是空话建议，是可直接用的改写稿：**

### 5.1 问题回答重写

针对每个🔴和🟡问题，给出：

```markdown
### 原回答（问题）
> 原文引用（带时间戳）

❌ 问题：具体问题分析

### 建议改写
> 可直接念的改写版本（符合用户语气库风格）

💡 改法说明：为什么这样改更好
```

### 5.2 下次面试必带清单

| 类别 | 内容 |
|------|------|
| 开场30秒 | 一句话身份 + 核心亮点 + 为什么来这里 |
| 3个必须讲的故事 | 每个故事对应JD的一条核心要求 |
| 必须避开的坑 | 本次犯的错误，下次绝不重复 |
| 反问备选3个 | 有质量的面试官问题 |

### 5.3 岗位赛道评估（附加价值）

基于面试中暴露的匹配度，给出：
- **这个赛道适不适合他**（长期判断）
- **同公司其他更适配的岗**（如果有的话）
- **同类公司同类岗的推荐/规避**

> 例：快手风控复盘结论 → 内容风控/合规/平台治理赛道比泛运营更适配他

## Output format (固定交付格式)

```markdown
# 面试复盘 — <公司> <岗位> — <日期>

## 一、基本面
- 时长 / 形式 / 面试官数
- 总体评分 + 核心矛盾

## 二、亮点（N条）
每条：类型 + 原文引用 + 为什么好

## 三、问题（N条）
每条：级别(🔴🟡🟢) + 原文引用 + 为什么有问题 + 怎么改

## 四、改写稿
直接可用的重写版本

## 五、下轮面试行动清单
3个必讲故事 / 3个反问 / 避坑表

## 六、赛道判断
这个方向对不对 / 同公司其他选择
```

## Red lines

- 🔴 **Houston准则**：读不到的内容（图片/音频无法处理时），第一句必须是"我看不到这个，请转成文字"。在此之前不许输出任何关于内容的断言。
- 🔴 **不改写用户的语气**：改写稿要符合他的说话方式（参考语气库），不要写成AI味浓重的"官方答案"
- 🔴 **不编造面试官反应**：逐字稿里没有的非语言信息一律标注"未知"，不要脑补"面试官点头表示认可"
- 🔴 **不给虚假希望**：如果确实表现差，直说。安慰的话留到"赛道判断"里的长期视角
- 🔴 **数字和事实必须可追溯**：每条论断都要带原文引用位置

## Example

> 用户发来飞书妙记导出的快手风控政策岗逐字稿（12分37秒）
>
> 输出：《面试复盘-快手风控政策岗-2026-10-16.md》
>
> 核心：六步判断框架(亮点) + "欺骗没损失"立场冲突(红灯) + 时间线矛盾(黄灯)
> 结论：🟡黄灯偏红灯，能力过了卡在时间
> 赛道判断：内容风控/合规比泛运营更适配
