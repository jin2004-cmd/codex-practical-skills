# Job search tracking

Read this reference when the memory work is about an ongoing internship or job search, where facts, deadlines, interviews, and goals change more often than anything else in the vault.

## Three layers inside the active area

- `CURRENT.md`: latest facts, deadlines, pending confirmations, and next actions.
- `STABLE.md`: durable background, skills, constraints, goals, and decision principles.
- `EVENT-LOG.md`: dated events with evidence level and outcome.

Read `CURRENT.md` first. Treat older notes as historical evidence, not current truth. The exact filenames follow the vault convention declared in the project AGENTS.md; the layering is what matters.

## Rules

1. Confirm the applicable local date and any early-morning convention before recording anything.
2. Separate facts, preferences, inferences, and unknowns.
3. Mark evidence as strong, medium, or weak.
4. Never turn an impression into an interview result.
5. Never invent salary, conversion, company, responsibility, or project data.
6. Update the current table and append a dated log entry whenever a state changes.
7. Keep missing information visible for the next conversation.

Describe transferable skills without changing the user's actual title or claiming duties they did not perform.

Lead outputs with a decision or status sentence, followed by facts, tradeoffs, unknowns, and the next action.

## Example

Ask "which companies am I still waiting on" and the answer is read from `CURRENT.md` only, so a deadline from last month can never be reported as today's status.

```
CURRENT.md   今天的事实：投递进度、待确认项、下一步
STABLE.md    不变的背景：学历、方向、硬约束
EVENT-LOG.md 带日期的旧记录，只追加不改写
```
